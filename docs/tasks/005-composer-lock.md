# Task 005 — Commit Composer lock file

## Goal

Close the remaining reproducibility gap from Tasks 003/004 by committing `composer.lock` generated from the current `composer.json` without changing dependency constraints or adding unrelated code changes.

## Required context

Before implementation read:

- `AGENTS.md`
- `docs/tasks/004-orm-schema-corrections.md`
- current `composer.json`
- current `.github/workflows/ci.yml`

Use `$implement-task`.

## Scope

Implement only:

1. Generate `composer.lock` from the current `composer.json`.
2. Commit the generated lock file.
3. Ensure GitHub Actions installs dependencies from the committed lock file.
4. Verify Composer validation and PHPUnit still pass.

Do not implement:

- dependency upgrades beyond what is required to produce the lock file;
- changes to `composer.json` constraints unless generation is impossible without a clearly documented technical correction;
- ORM changes;
- admin UI;
- product links;
- collectors;
- parsing;
- queue/agents;
- refactoring unrelated files.

## Requirements

The committed `composer.lock` must correspond to the current `composer.json`.

The expected CI behavior after this task is that the Composer install step reports installation from the lock file rather than resolving the dependency graph from scratch.

Do not manually author or edit package versions inside `composer.lock`. Generate it using Composer.

If the Codex execution environment cannot reach Packagist, do not fabricate a lock file. In that case, state the limitation clearly and do not claim the task is complete.

## Verification

Before completion:

1. run `composer validate`;
2. run `composer install --no-interaction --prefer-dist` using the generated lock file;
3. run PHPUnit;
4. run `git diff --check`;
5. confirm the final diff is limited to `composer.lock` unless a strictly necessary technical correction is documented.

GitHub Actions must be green.

## Acceptance criteria

Task is complete when:

- `composer.lock` exists in the repository;
- it was generated by Composer from the current dependency constraints;
- `composer.json` constraints are unchanged unless a necessary correction is documented;
- CI installs from the committed lock file;
- `composer validate` succeeds;
- PHPUnit succeeds;
- no unrelated files are changed.
